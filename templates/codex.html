Codex Guide

把需求讲清楚，AI 才能把活做清楚

Codex 可以协助阅读项目、修改文件、运行命令和整理结果。它不是保证一次成功的魔法工具，更适合在明确目标、边做边验收的过程中，帮助普通人把想法推进成可运行的小工具。

01

Codex 简介

Codex 是能阅读项目文件、修改代码、运行检查并解释结果的 AI 编程协作者。你给它目标和边界，它把目标拆成可以执行的步骤。

02

普通人的使用场景

它适合把重复流程做成小工具：报名表、订单整理、学习清单、活动页面、资料归档、简单后台和自动检查。

03

先从小项目开始

选择一个低风险、能快速验证的小需求，练熟“提出需求、分步执行、检查结果”的流程，再考虑更大的系统。

04

好提示词的结构

目标：说明最终要得到什么。背景：补充使用者、场景和已有文件。约束：写清哪些文件能改、哪些不能改。输出格式：说明要页面、清单、表格还是说明文档。验收标准：明确怎样算完成，例如页面能打开、文案包含指定内容、测试通过。

05

06

常见错误

一次性需求太大：先做最小可用版本。没有验收标准：Codex 很难判断结果是否符合期待。文件边界不清：容易误改配置、数据或生产相关文件。不让它测试：只看命令成功不够，要确认真实页面或流程能用。

07

不要给敏感密钥

不要把 API Key、账号密码、私有证书或客户隐私直接写进提示词或提交到代码里。

08

不要直接操作重要生产数据

先使用复制的数据、测试文件或小样本。重要数据要备份，并保留人工确认环节。
